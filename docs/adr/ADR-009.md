# ADR-009: Estrategia de despliegue, contenerización y procedimiento de reversión

**Estado:** Aprobado  
**Fecha:** 2026-10-25  
**Autor:** Equipo FitZone Sports  
**Sprint:** 4 (Unidad V)  

## Contexto
Para garantizar reproducibilidad entre los entornos de desarrollo, evaluación y operación de FitZone Sports en el marco de la Unidad V, se requiere empaquetar el backend (Node.js/Express) y el frontend (SPA React/Vite) evitando discrepancias de versiones de dependencias o sistema operativo. Asimismo, es indispensable definir un flujo claro de despliegue y un procedimiento rápido y seguro de reversión (*rollback*) ante cualquier falla crítica detectada tras liberar una nueva versión.

## Decisión
Se adopta una estrategia de **despliegue contenerizado con Docker y Docker Compose**, versionado mediante etiquetas de Git (`tags` anotados e imágenes etiquetadas por versión):
- **Contenerización de servicios:**
  - `backend/Dockerfile`: Imagen ligera basada en Node.js que instala dependencias de producción y expone la API REST de Express con endpoint de verificación de salud (`/health`).
  - `frontend/Dockerfile` + `nginx.conf`: Construcción *multi-stage* con Vite para generar los estáticos optimizados de React y servirlos mediante **Nginx**, configurando respaldo de rutas SPA (`try_files`) y proxy hacia el servicio backend.
- **Orquestación (`docker-compose.yml`):** Archivo en la raíz que levanta y enlaza los contenedores (`frontend` y `backend`), inyecta variables de entorno externas (`.env` con credenciales de PostgreSQL/Supabase, secreto JWT y claves de pasarela) y gestiona políticas de reinicio y *healthchecks*.
- **Procedimiento de reversión (*rollback*):**
  1. Identificar el último tag/versión estable previo en Git (por ejemplo, `v1.0-estable` o tag de release anterior) y detener los contenedores actuales (`docker compose down`).
  2. Hacer *checkout* del tag estable previo (`git checkout <tag-estable>`) o apuntar las imágenes Docker a la etiqueta anterior conocida como estable.
  3. Reconstruir/levantar los contenedores de esa versión (`docker compose up -d --build`) y verificar la disponibilidad mediante el endpoint `/health` y los flujos críticos de acceso y reservas.
  4. Si la liberación incluyó migraciones de esquema en PostgreSQL, aplicar el script de reversión correspondiente o restaurar el respaldo previo antes de rehabilitar el tráfico.

## Consecuencias
**Positivas:**
- [+] Entorno idéntico y reproducible en cualquier máquina con Docker, eliminando el problema de diferencias locales de configuración.
- [+] Separación limpia entre los activos estáticos servidos por Nginx y la lógica de API en Node.js dentro de una misma red interna de contenedores.
- [+] Reversión rápida y determinística a un tag o imagen estable previa en pocos minutos.

**Negativas:**
- [-] Introduce la necesidad de mantener sincronizados los archivos `Dockerfile`, `nginx.conf`, `docker-compose.yml` y la plantilla `.env.example` ante cambios de puertos o variables.
- [-] Las reversiones que involucren cambios estructurales en PostgreSQL requieren disciplina en el versionado de scripts SQL para no perder compatibilidad hacia atrás.

**Deuda asumida:**
- [-] Automatizar en el futuro la publicación de imágenes versionadas en un registro de contenedores (como GitHub Container Registry) para acelerar aún más el rollback sin reconstrucción local.

## Alternativas consideradas
| Alternativa | A favor | En contra | Por qué se descartó |
|---|---|---|---|
| Despliegue manual directo sobre el sistema operativo anfitrión (sin contenedores) | No requiere instalar Docker ni mantener archivos de imagen. | Propenso a diferencias de versiones de Node.js, variables de entorno y configuración de servidor web entre equipos. | Descartada por falta de reproducibilidad y mayor riesgo de errores humanos durante despliegues y reversiones. |
| Orquestación con Kubernetes | Alta disponibilidad, autoescalado y despliegues *rolling/canary* avanzados. | Complejidad operativa y consumo de recursos desproporcionados para el alcance del proyecto y equipo. | Descartada frente a Docker Compose por simplicidad operativa y adecuación al alcance del TIF. |
