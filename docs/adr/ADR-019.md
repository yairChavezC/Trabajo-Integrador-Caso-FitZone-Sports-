# ADR-019 — Estrategia de pruebas del módulo M3

- **Estado:** Aceptado
- **Fecha:** 2026-11-16
- **Autor:** Acosta, Marcela
- **Sprint:** 5
- **Requisitos relacionados:** RNF-03

## Contexto

El módulo M3 requiere pruebas que cubran lógica de negocio, integración con PostgreSQL y concurrencia.

## Alternativas consideradas

| Alternativa | A favor | En contra | Por qué se descartó |
|---|---|---|---|
| Solo unitarias | Rápidas | No validan BD ni concurrencia | Descartada |
| Solo integración | Validan todo | Lentas, requieren DB | Descartada |
| Pirámide: unitarias + integración + concurrencia | Cobertura completa | Requiere configurar DB de prueba | **Adoptada** |

## Decisión

- **Unitarias (68):** servicios, repos, dominio, DTOs, controladores, observers — con repos mock.
- **Integración (12):** PostgreSQL real — reservas, cancelaciones, lista de espera, penalidad.
- **Concurrencia (1):** dos reservas simultáneas sobre cupo=1 — solo una confirma.

Cobertura mínima por archivo núcleo: líneas ≥ 80%, funciones ≥ 70%, ramas ≥ 50%.

## Consecuencias

- **Positivas:** Confianza en que el módulo funciona end-to-end.
- **Negativas:** Las de integración requieren `TEST_DATABASE_URL`.
- **Deuda asumida:** Agregar pruebas E2E con navegador.
